# Phase 0 — Skeleton: design

Date: 2026-09-23 · Status: awaiting review · Parent: `Spica — MVP build spec.md` (§7, Phase 0)

## 1. Goal and exit test

Build the skeleton every later phase layers onto: chat UI, auth, `session_log`,
the full database schema, a memory inspector stub and an eval harness stub.

**Exit test (spec §7):** a conversation works end to end and is stored.
Concretely: a signed-up adult user sends messages in `/chat`, receives replies
from the reply model, and both sides are persisted in `session_log`; the Phase 0
eval scripts (§7 below) pass.

**In scope:** everything above, plus the guardrails that apply in every phase
(spec §9.2): age gate, crisis handling, `user_id` scoping, account deletion,
encryption at rest.

**Out of scope (later phases):** retrieval, extraction, reconciliation, any fact
/ entity / thread / identity / relationship writes, ego, reach-outs, push,
personality test. Tables exist; behaviour does not.

## 2. Decided inputs

| Topic | Decision |
| --- | --- |
| Language / framework | TypeScript full-stack: Next.js (App Router), current Node LTS, pnpm |
| ORM / migrations | Drizzle ORM + drizzle-kit |
| Database | Postgres 16 + pgvector; local via `docker-compose.yml` |
| Job queue | pg-boss (runs inside the same Postgres — one database) |
| Reply model | Anthropic `claude-sonnet-5` (config) |
| Cheap strict-JSON model | Anthropic `claude-haiku-4-5-20251001` (config); used in P0 only for the crisis classifier |
| Embeddings | Voyage AI `voyage-3.5`, 1024 dims (config); wired but unused until Phase 1 |
| Auth | Better Auth, email + password, tables in our Postgres |
| Tests | Vitest against a real Postgres (docker), `FakeLLMProvider` |
| Layout | Single package; framework-free `src/core` (approach A) |

The LLM provider may change later; all model access goes through the
`LLMProvider` interface so a swap touches one adapter plus config.

## 3. Architecture

```
src/
  core/                 framework-free; never imports Next
    clock.ts            Clock interface: SystemClock | SimClock
    config.ts           all numeric constants + model IDs; zod-validated; env overrides
    llm/                LLMProvider interface, AnthropicProvider, FakeLLMProvider
    embed/              Embedder interface, VoyageEmbedder, FakeEmbedder
    prompts.ts          loads versioned prompt files from /prompts
    chat/               handleUserMessage(), assembler, session resolution
    safety/             crisis check (classifier + keyword fallback)
    deps.ts             Deps bundle: { db, clock, llm, embedder, queue, config }
  db/
    schema.ts           Drizzle schema: spec §3 tables + trace tables + Better Auth tables
    repos/              one module per table; every function takes userId first
    migrations/         generated by drizzle-kit
  app/                  Next.js routes, pages, route handlers
  worker/               pg-boss worker entrypoint; registers job handlers
prompts/
  reply/v1.md           placeholder persona + memory-use rule + crisis + identity disclosure
  safety/crisis-classifier/v1.md
evals/
  scripts/*.yaml
  run.ts
  baseline.json
  results/              gitignored
DECISIONS.md
docker-compose.yml
```

**Rules.**

- Every entry point that produces a companion reply (chat route, eval harness,
  and in Phase 3 reach-outs) calls `core.chat.handleUserMessage`.
- `core` receives all side-effecting dependencies via `Deps`; nothing in `core`
  reads `Date.now()`, `process.env` or a global DB client directly.
- Prompts are files under `prompts/<name>/v<N>.md`; the active version per
  prompt is set in config.

## 4. Data model

All six spec §3 tables are created in Phase 0 with field names exactly as in
the spec. Additions (§4.3) are also written back into the MVP spec.

### 4.1 Conventions

- Enums are Postgres enums: `fact_subject` (user|self|shared),
  `entity_subject` (user|self), `fact_kind`, `fact_status`, `fact_source`,
  `entity_type`, `thread_status`, `thread_stakes`, `session_role`
  (user|companion), `session_trigger` (reach_out; column nullable).
- Float ranges from the spec are CHECK constraints (e.g. `salience BETWEEN 0 AND 1`,
  `valence BETWEEN -1 AND 1`).
- Every table has `user_id uuid NOT NULL REFERENCES "user"(id) ON DELETE CASCADE`.
  Deleting the auth user row deletes all of that user's data.
- **No `DEFAULT now()` on any timestamp column.** All timestamps are written
  from the injected `Clock`, so simulated time in evals never mixes with
  wall-clock time.
- Embedding dimension is defined once in config (`embedding.dimensions = 1024`);
  the schema reads it, and startup fails if the configured embedder reports a
  different dimension.

### 4.2 Spec tables

| Table | PK | Indexes / notes |
| --- | --- | --- |
| `fact` | `id` | HNSW (`vector_cosine_ops`) on `embedding`; GIN on `entity_refs`; `(user_id, status)`; `superseded_by` → `fact.id`; `thread_id` → `thread.id` |
| `entity` | `id` | `(user_id, subject)`; GIN on `aliases` |
| `thread` | `id` | `(user_id, status, next_checkpoint)` |
| `identity` | `user_id` | values fields and ego fields as flat columns per spec §3.4; `preoccupation` → `fact.id` ON DELETE SET NULL |
| `relationship` | `user_id` | per spec §3.5 |
| `session_log` | `id` | `(user_id, created_at)`; partial `(user_id) WHERE extracted = false`; `(user_id, session_id)` |

Phase 0 writes only `session_log` (and auth tables). No `identity` or
`relationship` rows are created until the phase that owns their defaults.

### 4.3 Additions (approved; logged in DECISIONS.md and added to the MVP spec)

1. **Session boundary.** A user turn starts a new `session_id` when the gap
   since the user's previous turn exceeds `session.idle_gap_minutes`
   (default 30). No separate session table.
2. **Inspector trace tables** — diagnostic logs, never read by the chat loop,
   so not a second memory store:
   - `retrieval_trace`: `id, user_id, turn_id → session_log.id, fact_id → fact.id,
     sim, fact_salience, entity_salience, recency, score, forced bool, created_at`
   - `ego_tick`: `id, user_id, mood_valence, mood_arousal, energy,
     preoccupation, reason text, created_at`
   - `reach_out_log`: `id, user_id, candidates jsonb, winner jsonb nullable,
     gate_results jsonb, sent bool, turn_id nullable → session_log.id, created_at`
3. **`session_log.safety_flag`** `jsonb, nullable` on companion turns:
   `{flagged, category, source: "classifier" | "keyword_fallback"}`.

## 5. Chat flow

`POST /api/chat` body `{ clientMessageId: uuid, text: string }` → authenticate
→ `handleUserMessage(deps, userId, input)` → `{ turnId, text, parts[], crisisCard? }`.

**Hot path.**

1. **Receive.** `now = clock.now()`. Resolve `session_id` (§4.3.1). If a
   `session_log` row with `id = clientMessageId` already exists for this user,
   reuse it (retry path); otherwise insert the user turn, `extracted = false`.
   If a companion turn already answers it, return that instead of regenerating.
2. **Retrieve.** Phase 0 returns an empty `RetrievalResult`.
3. **Assemble.** The six-slot assembler in spec §4.1 order, empty slots
   skipped: (1) values doc from `prompts/reply/v1.md`; (2)–(5) empty in P0;
   (6) last `chat.recent_turns` (20) turns of this user's `session_log`.
4. **Generate + crisis check, in parallel** (`Promise.all`):
   - reply call to the reply model;
   - crisis classifier on the cheap model, strict JSON `{flag, category}`,
     timeout `safety.classifier_timeout_ms` (default 3000). On error or
     timeout, fall back to a conservative keyword list (config).
   - If flagged, attach the crisis-resources card from config. The card is
     appended by code rather than left to the model, so it always appears.
     The reply prompt also always instructs the companion to respond caringly
     and in character.
5. **Send + log.** Insert one companion `session_log` row per reply with
   `safety_flag`. Split the text on blank lines into `parts` (at most
   `chat.max_parts`, default 4) for texting-style bubbles. Enqueue `cold_path`
   `{userId, turnIds}` inside a try/catch — enqueue failure is logged, never
   surfaced. Return.

**Cold path (P0).** The `cold_path` job handler is registered and intentionally
does nothing; turns stay `extracted = false`, so Phase 1 processes the whole
Phase 0 history.

**Error handling.**

| Failure | Behaviour |
| --- | --- |
| Reply model error / timeout | User turn stays stored; 503; UI marks "not delivered · retry"; retry resends same `clientMessageId` |
| Crisis classifier error / timeout | Keyword fallback; `safety_flag.source = "keyword_fallback"` |
| Queue enqueue error | Logged; reply still returned |
| Unauthenticated | 401 |

**UI.**

- `/signup`: email, password, date of birth. Server rejects under
  `auth.min_age` (18). DOB is stored on the user record.
- `/login`, `/chat`, `/settings`.
- `/chat`: single conversation, last 50 turns, typing indicator, texting-style
  bubbles, crisis card rendered distinctly. No streaming.
- `/settings`: "Delete account" with confirmation → deletes the user row
  (cascade) and signs out.

## 6. Memory inspector stub

- Route `/inspector`. Enabled only when `INSPECTOR_ENABLED=true` (default
  false in production, true in development) and the signed-in email is in
  `INSPECTOR_ADMIN_EMAILS`. Both checks run server-side in the layout and in
  every loader.
- Read-only. Pick a user; all queries go through the same `userId`-scoped repos.
- Tabs, all querying real tables, with an empty state that names the phase
  that fills them:
  - **Transcript** — `session_log` grouped by `session_id`; shows `extracted`,
    `trigger`, `safety_flag`.
  - **Facts** — filter by subject, status, entity, thread; sort by salience,
    recency.
  - **Entities & Threads** — each with linked facts.
  - **Identity & Relationship** — values, current ego, `ego_tick` history,
    relationship row.
  - **Retrieval** — per companion turn, `retrieval_trace` rows with the four
    factors and `forced`.
  - **Reach-outs** — `reach_out_log`.
- Server components and plain tables; no charts.

## 7. Eval harness stub

- `pnpm eval [--llm=fake|real] [--compare] [--only <name>]`.
- Scripts: YAML in `evals/scripts/`:

  ```yaml
  name: exit-two-sessions
  sessions:
    - at: "day 0 09:00"
      turns: ["hey, long day", "my sister Mia got into uni"]
    - at: "+7d"
      turns: ["back again"]
  assertions:
    - type: state
      query: session_count
      expect: 2
  ```

- Runner: separate eval database (`EVAL_DATABASE_URL`), migrated at start and
  truncated between scripts; one fresh user per script; `SimClock` set to each
  session's `at`; each turn goes through `handleUserMessage`; after each turn
  the cold path is drained synchronously by invoking the job handler directly
  (deterministic, no pg-boss polling).
- Assertions: the script schema and registry define all five spec §8.2 types.
  Phase 0 implements `state` (named, parameterised SQL checks — row counts,
  statuses, fields). `recall`, `no_false_recall`, `consistency` and
  `reach_out` report as **skipped** ("implemented in Phase N"), never passed.
- Output: console summary + JSON report in `evals/results/<timestamp>.json`.
  `--compare` exits non-zero if any script that passes in the committed
  `evals/baseline.json` does not pass now.
- Phase 0 scripts:
  1. `exit-two-sessions` — two sessions a week apart; turns stored in order,
     2 distinct `session_id`s, companion replies non-empty, all
     `extracted = false`.
  2. `crisis-flag` — a crisis message sets `safety_flag.flagged` and returns
     the crisis card.
  3. `user-isolation` — two users converse; neither transcript contains the
     other's turns.

## 9. Guardrails in Phase 0

| Guardrail | Implementation |
| --- | --- |
| Age gating | DOB required at signup; server-side 18+ check; no minor-facing features |
| Crisis handling | Parallel classifier + keyword fallback on the hot path; code-appended resource card |
| `user_id` scoping | Repo functions take `userId` first; no unscoped helper; isolation test + eval |
| No cross-user facts | Assembler reads only the requesting user's rows (P0: turns only) |
| Account deletion | Single delete of the user row; FK cascades |
| Encryption at rest | Storage-level (managed Postgres / encrypted disk); logged in DECISIONS.md |
| No manipulation | Placeholder persona prompt forbids guilt/pressure language |

Open decisions (spec §9.1) are not settled here. The only one touched in
Phase 0 is **identity disclosure**, implemented as its stated placeholder in
`prompts/reply/v1.md`.

## 10. Testing

Vitest, real Postgres from `docker-compose`, `FakeLLMProvider` and
`FakeEmbedder`, `SimClock`.

- Chat round-trip stores user + companion turns with correct `session_id`.
- Retry with the same `clientMessageId` does not duplicate turns.
- Session split exactly at `idle_gap_minutes`.
- Crisis: classifier flag → card; classifier timeout → keyword fallback.
- Enqueue failure does not fail the reply.
- Isolation: user B's queries never return user A's rows.
- Account deletion removes rows from every table.
- Signup rejects DOB under 18.
- Assembler slot order and empty-slot skipping.
- Inspector access denied without the flag or allowlist.

Plus `pnpm eval --llm=fake --compare` in the definition of done.

## 11. Definition of done (Phase 0)

- `pnpm typecheck`, `pnpm lint`, `pnpm test` pass.
- `pnpm eval --llm=fake --compare` passes; one `--llm=real` run passes
  `exit-two-sessions` and `crisis-flag`.
- Manual exit test: sign up, chat across two sessions, see both in
  `/inspector` Transcript.
- MVP spec updated with §4.3 additions; `DECISIONS.md` has an entry for each
  uncovered choice; CLAUDE.md "Current phase" set to 0 and working
  conventions filled in.
